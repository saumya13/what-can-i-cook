# ChefMate — Backend

Express + TypeScript API. Generates recipes and dish photos via [OpenRouter](https://openrouter.ai), and persists saved recipes to Postgres and their photos to Storage, both on [Supabase](https://supabase.com).

## Prerequisites

- Node.js `>=22` (required by `@supabase/supabase-js`)
- A Supabase project
- An OpenRouter API key with access to `google/gemini-3.8-flash` (recipe text) and `google/gemini-3.1-flash-image` (dish photos)

## Setup

1. **Install dependencies**

   ```bash
   npm install
   ```

2. **Create the `recipes` table** in your Supabase project's SQL editor:

   ```sql
   create table if not exists recipes (
     id bigint generated by default as identity primary key,
     name text not null,
     ingredients text not null,
     instructions text not null,
     description text,
     cuisine text,
     servings bigint,
     cook_time text,
     image_url text
   );
   ```

3. **Create a Storage bucket** named `recipes`, and mark it **Public** — the backend saves dish photos there and stores their public URL, so a private bucket will upload fine but the images won't load in the browser.

4. **Configure environment variables**

   ```bash
   cp .env.example .env
   ```

   | Variable                    | Description                                                                                                                    |
   | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
   | `OPENROUTER_API_KEY`        | OpenRouter API key used for both recipe text and image generation.                                                             |
   | `DATABASE_URL`              | Postgres connection string (Supabase → Project Settings → Database).                                                           |
   | `SUPABASE_URL`              | Your Supabase project URL.                                                                                                     |
   | `SUPABASE_SERVICE_ROLE_KEY` | Supabase **service role** key. Server-side only — it bypasses Row Level Security, so never expose it to a client or commit it. |

5. **Run it**

   ```bash
   npm run dev
   ```

   The API runs at `http://localhost:3000` by default (override with `PORT`).

## Scripts

| Command         | Description                                                        |
| --------------- | ------------------------------------------------------------------ |
| `npm run dev`   | Start the API with `tsx watch` (auto-restarts on file changes).    |
| `npm run build` | Compile TypeScript to `dist/`.                                     |
| `npm start`     | Run the compiled build (`dist/src/server.js`) — run `build` first. |

## API reference

All request/response bodies are JSON.

| Method   | Path                   | Description                                                                                                                            |
| -------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/health`              | Health check. Returns `{ "status": "ok" }`.                                                                                            |
| `GET`    | `/api/recipes`         | List all saved recipes.                                                                                                                |
| `GET`    | `/api/recipes/:id`     | Get one saved recipe. `404` if it doesn't exist.                                                                                       |
| `POST`   | `/api/recipes`         | Save a recipe to the cookbook.                                                                                                         |
| `DELETE` | `/api/recipes/:id`     | Delete a saved recipe (and its stored photo, if any).                                                                                  |
| `POST`   | `/api/recipe/generate` | Generate a new recipe from `{ ingredients: string[], preferences: { vegetarian: boolean, spiceLevel: "mild" \| "medium" \| "hot" } }`. |

## Project structure

```
src/
├── config.ts              # Validated environment variables — fails fast on startup if any are missing
├── prompts.ts              # The system prompt sent to the recipe model
├── types.ts                 # Shared TypeScript types
├── lib/
│   ├── openrouter.ts        # Calls OpenRouter for recipe text and dish images
│   ├── recipeParser.ts      # Turns the model's raw text response into a typed recipe
│   └── supabaseStorage.ts   # Uploads/deletes dish photos in Supabase Storage
├── middleware/
│   └── errorHandler.ts      # Final error-handling middleware — returns JSON instead of a stack trace
├── routes/
│   ├── recipes.ts           # /api/recipes CRUD
│   └── generateRecipe.ts    # /api/recipe/generate
└── server.ts                # App bootstrap — wires the above together
```

Database access uses Drizzle ORM (`drizzle/schema.ts`, `drizzle/db.ts`); there's no migration tooling wired up yet, so schema changes need to be applied by hand in Supabase's SQL editor (see step 2 above).
